# Mini Manga 0.2.7 性能修复

日期：2026-11-02。

## 检查结论

本机只读检查显示书库 129 条记录、收藏 5 条，完整书籍列表查询约 0.75ms，序列化约 39KB；单靠书库记录量不能解释明显卡顿。缩略图缓存已有 1,890 个文件，旧代码却在每次写入一张缩略图后重新遍历整个目录。

使用隔离的 2,000 个生成缓存文件、30 次连续请求测量，旧逻辑执行 30 次目录遍历、60,000 次 stat，约 3,581ms；修复后执行 1 次遍历、2,030 次 stat，约 67ms。这是缓存维护的微基准，不能当成整台电脑或完整软件启动的加速倍数。

200 个生成漫画目录的树展开后，旧版包含 201 个尚未打开的操作菜单内容，共 3,418 个树内元素；修复后关闭菜单不挂载内容，树内元素为 1,207 个。所有目录仍可访问，不删除书库记录。

## 修改文件与行为

| 文件 | 修改 |
| --- | --- |
| `src/main/cache.ts` | 缓存大小增量记账；每分钟重新核对；有界并发读取元数据；保护排队中的当前输出；只管理缓存目录内符合命名规则的文件 |
| `src/main/index.ts` | 当前层目录最多 16 个并发检查、批量写数据库；同一缩略图共享任务并原子发布；AI 与 PDF 延迟初始化 |
| `src/main/worker.ts` | 图片处理库在第一项缩略图任务时加载，数据库读取不再等待它初始化 |
| `src/renderer/SourceTree.tsx` | 操作菜单打开后才挂载收藏评分；收起目录不重新打开或索引；目录树不随每次翻页重复渲染 |
| `src/renderer/Favorites.tsx` | 操作控件复用 30 秒内的收藏数据，修改收藏后仍显式刷新 |
| `src/renderer/main.tsx` | 稳定目录回调；切回窗口时不自动重读全部查询；版本升级到 0.2.7 |
| `tests/cache.test.cjs`、`tests/performance.cjs` | 缓存配额与文件保护、扫描次数、目录 DOM、收起不索引及首次 AI 初始化回归 |

AI 功能仍在第一次使用时载入预设并恢复中断任务状态；PDF 第一次打开时启动渲染 Worker。缓存定期核对用于识别其他实例或外部清理造成的变化。首次读取新图片、压缩包或冷磁盘仍需要实际 I/O。

## 验证范围

类型检查、生产构建、12 项单元/Worker 测试通过。源码真实窗口测试通过：基础阅读、阅读器升级、收藏/PDF/WebP、来源导航、读后推荐、逐层加载、侧栏及 AI 修改。AI 测试使用本机临时模拟服务，没有发送个人图片或调用真实生成模型。

所有性能样例、数据库和输出均为生成内容。对正常数据只读统计，没有清空个人缓存、改动收藏或读取个人漫画画面。未验证网络盘离线、大型压缩流、超大目录的完整性能，也没有证明这是机器上所有卡顿的唯一原因。

## 启动测试

从机械盘运行打包程序时，首次受测启动约 13,035 ms，复开约 354 ms。SSD 运行副本首次受测启动约 1,998 ms，导入 200 个生成目录约 84 ms。首次加载、系统文件缓存和安全软件检查可能影响结果，这组数据仅代表测试当次的条件。

运行副本逐一通过 SHA-256 校验，性能约束和基础阅读回归通过。
